# 链鉴 AML 产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 链鉴 AML：反洗钱证据链审查平台 |
| 文档用途 | 华为黑客松演示版产品和验收基线 |
| 当前版本 | 演示版 MVP |
| 数据范围 | IBM AML-Data `HI-Small` 合成数据子集 |
| 当前主前端 | React + Vite |
| 当前后端 | Python + FastAPI |
| 当前存储 | SQLite；Neo4j 为可选图谱服务 |
| 重要限制 | 不接入真实银行核心系统，不替代人工判断 |

## 2. 产品概述

链鉴 AML 面向银行合规调查人员，将交易数据、规则命中、账户画像、资金关系图谱、风险评分、证据解释、Agent 调查、人工审核和审计留痕整合到同一工作台。

产品解决的是“告警产生后如何快速理解、核验和留痕”的问题，而不是自动作出账户处置或监管报送决定。所有调查结论都必须回到可查询的交易、账户、规则和图谱事实。

## 3. 用户与场景

### 3.1 目标用户

1. 合规调查人员：查看告警、资金路径和支持结论的交易证据；
2. 审核负责人：复核调查结论，确认、驳回或要求补充调查；
3. 风险分析人员：分析规则命中、风险分布和关联账户；
4. 技术与运维人员：查看数据质量、规则命中、服务健康和 Agent 运行情况。

### 3.2 典型场景

- 一个账户在短时间内向多个账户拆分转账；
- 多个账户先向一个账户归集，再向其他账户转出；
- 资金在多个账户之间循环回流；
- 单笔交易正常，但多跳资金链呈现明显的关联结构；
- 调查人员需要快速形成可复核的报告草稿。

## 4. 问题与目标

### 4.1 现有问题

- 告警数量多，人工逐笔追踪耗时；
- 单笔交易不足以解释复杂的多跳、循环或拆分行为；
- 规则命中原因和关键证据分散在不同系统；
- 调查报告依赖人工整理，口径不统一；
- 审核意见、证据版本和处置过程缺少统一留痕。

### 4.2 MVP 目标

- 对演示数据运行规则并生成预警案件；
- 为预警关联账户、交易、规则和资金路径；
- 展示风险评分组成和关键因素影响；
- 生成基于事实数据的结构化调查报告；
- 支持人工确认、驳回、补充调查和审核备注；
- 记录调查和审核过程，形成可追溯闭环。

### 4.3 非目标

- 不进行真实客户身份识别；
- 不接入真实银行核心、支付或监管报送系统；
- 不自动冻结账户、拒绝交易、限额或提交可疑交易报告；
- 不输出洗钱定性、法律意见、投资或授信结论；
- 不把测试标签用于在线预警、图谱或 Agent 推理；
- 不在本 MVP 中承诺生产级吞吐、召回率或昇腾性能。

## 5. 数据与合规边界

### 5.1 数据来源

当前项目使用 IBM AML-Data `HI-Small` 的演示子集，包含账户、交易、案例和离线评估标签。数据为合成数据，不对应真实银行客户或真实交易。规模、生成参数和许可信息以 [DATASET_README.md](../data/DATASET_README.md) 与 [manifest.json](../data/manifest.json) 为准。

### 5.2 标签隔离

`labels.csv` 及数据库中的评估标签仅能由离线评估模块读取。在线规则、风险评分、图谱查询、Agent 工具和报告生成不得读取标签字段。

### 5.3 输出边界

模型或规则输出必须标明：

- 这是调查辅助结果；
- 结论基于当前可用数据和规则；
- 关键判断应回到交易或图谱证据；
- 最终处置由有权限的人工审核人员完成。

## 6. 核心业务流程

```mermaid
flowchart LR
    A[导入账户与交易数据] --> B[清洗与数仓落地]
    B --> C[规则检测与风险评分]
    C --> D[生成预警案件]
    D --> E[构建证据链与账户画像]
    E --> F[查询资金图谱]
    E --> G[Agent 调查与报告草稿]
    F --> G
    G --> H[人工审核]
    H --> I[处置记录与审计日志]
    I --> J[监控、评估与迭代]
```

## 7. 功能需求

### 7.1 数据导入与清洗

系统应支持：

- 读取账户、交易、案例和评估标签文件；
- 检查交易 ID、时间、付款方、收款方、金额、币种等必填字段；
- 统一时间和金额格式；
- 记录导入批次、源文件、清洗结果和质量状态；
- 输出可供规则、图谱和查询服务使用的标准数据。

当前实现：支持本地 CSV 清洗和 SQLite 数仓重建；通用上传式数据管理页面仍属于后续增强项。

### 7.2 可疑行为检测

首期规则包括：

- 循环交易；
- 拆分转账；
- 资金归集和资金发散；
- 多跳资金转移；
- 快速转移或短期高频行为；
- 账户关联和行为组合规则。

每个预警至少包含：预警编号、涉及账户、关联交易、命中规则、风险评分、风险等级、生成时间和处理状态。

### 7.3 风险评分与解释

风险评分应满足：

- 分项贡献可展示；
- 分项合计与总分一致；
- 评分因素可追溯到规则或交易证据；
- 支持移除某个因素后的反事实分析；
- 明确评分不是法律定性或自动处置依据。

评分权重只作为当前演示版实现参数，不能在 PRD 中视为已验证的生产权重。任何权重或阈值变更都应经过离线评估和人工审核。

### 7.4 资金图谱

图谱以账户为节点、交易为边，至少支持：

- 查看资金流向；
- 查询 1–3 跳关联路径；
- 展示交易时间、金额、交易 ID 和风险标记；
- 高亮规则涉及的账户和关键路径；
- 查看账户摘要和关联关系；
- 在 Neo4j 不可用时使用 SQLite 事实数据提供有限降级能力。

### 7.5 调查 Agent

Agent 可接收预警编号或调查问题，并调用受限工具查询：

- 预警详情；
- 命中规则；
- 关键交易；
- 账户画像；
- 资金路径；
- 评分解释和反事实结果。

输出必须包含：风险摘要、命中规则、关键证据、资金路径、待核查事项和免责声明。工具查询失败时必须显式报告失败，不得补造账户、金额、交易或路径。

### 7.6 调查报告

报告至少包括：

1. 案件编号和生成时间；
2. 涉及账户；
3. 风险等级和评分；
4. 预警摘要；
5. 可疑行为描述；
6. 关键交易证据；
7. 资金链路说明；
8. 命中规则和评分解释；
9. 建议核查事项；
10. 审核结论、审核人和备注；
11. 数据、模型和人工审核免责声明。

当前支持网页或 Markdown 形式的报告内容；正式 PDF 文件导出和报告版本管理尚未作为完成能力承诺。

### 7.7 人工审核与审计

审核人员可执行：

- 确认风险；
- 驳回预警；
- 标记需要补充调查；
- 添加审核备注；
- 更新案件处理状态。

系统应记录：操作人、操作时间、原状态、新状态、审核意见、案件编号和所引用证据版本。

## 8. 页面需求

### 8.1 调查工作台

展示案件头部、风险等级、账户信息、关键交易时间线、证据链、评分解释、反事实分析、图谱入口、报告入口和人工审核区域。

### 8.2 预警中心

支持按风险等级、规则类型、状态和时间筛选，并展示预警编号、涉及账户、评分、规则和更新时间。

### 8.3 图谱调查页

支持节点拖拽、画布缩放、资金方向、关系详情和关键路径高亮。图谱结果必须标明数据来源或降级状态。

### 8.4 监控与评估页

展示数据质量、规则命中、审核状态、Agent 任务、离线 Precision、Recall、F1 等指标。没有真实线上标签时，不得把离线指标表述为线上效果。

## 9. 技术方案

```text
React/Vite
    ↓ HTTP JSON
FastAPI
    ├─ Rule Engine → SQLite
    ├─ Evidence/Review/Audit → SQLite
    ├─ Agent Tools → SQLite + Neo4j（可选）
    ├─ Graph Intelligence → Neo4j 或 SQLite 降级
    └─ Evaluation/Monitoring
```

建议和当前实现的对应关系：

| 层 | 当前实现 |
|---|---|
| 前端 | `web/` React + Vite |
| 后端 | `backend/main.py` FastAPI |
| 规则 | `rules/` |
| 数仓 | `backend/core/` + SQLite |
| 证据和审核 | `app/`、`backend/api/` |
| 图谱 | `graph/`、`graph_intelligence/` |
| Agent | `agent/`、`agents/` |
| 评估 | `evaluation/` |
| 监控 | `monitoring/` |

Streamlit 页面和昇腾部署属于辅助或目标能力，不能与当前 React 主链路混写成已完成事实。

## 10. 质量与验收标准

### 10.1 MVP 功能验收

- 可加载项目演示数据；
- 可生成至少三类规则预警；
- 可查看账户、交易和 1–3 跳资金关系；
- 每个预警显示命中规则和关键交易证据；
- 可展示评分解释和反事实结果；
- Agent 可以基于工具数据生成调查摘要；
- 可生成结构化 Markdown 报告；
- 支持人工审核和审计记录；
- 标签只用于离线评估。

### 10.2 工程验收

代码修复后应重新执行并保存结果：

```powershell
python -m pytest -q
cd web
npm run build
npm run test:smoke
```

当前版本不能直接宣称全量测试通过，详见项目 [README](../README.md) 的验证状态。

### 10.3 评估指标

离线评估可计算 Precision、Recall、F1、PR-AUC、Precision@20 和 Precision@50。指标必须注明数据集、标签版本、规则版本和运行时间；不能把合成数据结果直接外推为生产效果。

## 11. 版本规划

### 当前演示版

- 预置数据加载；
- 规则检测和风险评分；
- 证据链、图谱和解释能力；
- Agent 调查和报告草稿；
- 人工审核和审计留痕；
- 基础监控与离线评估。

### 后续版本

- 真正的 PDF 导出和报告版本管理；
- 后端分页、权限和多租户；
- 规则配置后台和审批流程；
- 实时交易检测的稳定消费链路；
- 更完整的 Neo4j/SQLite 数据源管理；
- 昇腾环境部署、压测和回归；
- CI、前端交互测试和性能基线。

## 12. 风险与免责声明

本系统基于合成数据，仅用于技术验证、产品演示和调查辅助。任何风险等级、规则命中或模型输出都不构成洗钱认定、法律意见、账户处置指令或监管报送依据。生产使用前必须完成数据、模型、权限、审计、安全和监管要求的独立评估。
