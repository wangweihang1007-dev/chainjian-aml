# 链鉴 AML 商业方案（对外版）

## 商业化摘要

**面向中小金融机构的可解释反洗钱智能审查系统，帮助审核人员更快发现可疑交易、还原资金链路并完成合规留痕。**

系统结合规则检测、资金图谱和大模型调查能力，对预警进行风险排序、证据整理和报告辅助生成，最终由人工完成审核和处置。

| 客户问题 | 产品能力 | 给客户带来的价值 |
|---|---|---|
| 多跳、循环和拆分交易难以人工识别 | 规则检测与资金图谱 | 更快还原复杂资金关系 |
| 预警数量多，审核效率低 | 风险排序与 Agent 辅助调查 | 减少重复查询和资料整理 |
| 结论难以解释 | 证据链、交易明细与评分解释 | 方便内部复核和监管检查 |
| 处理过程缺少留痕 | 人工审核与审计日志 | 保留完整处置记录 |
| 规则长期不更新 | 监控、评估与人工审批迭代 | 及时发现规则效果下降 |

## 1. 面向的客户

链鉴 AML 第一阶段面向城商行、农商行和村镇银行，重点解决可疑交易预警产生之后的调查、证据整理和人工审核问题。这些机构通常已经有交易系统和基础预警能力，但调查人员仍然需要在多个系统之间查询交易、查找关联账户、整理资金路径和撰写报告。

支付机构、消费金融、跨境支付和其他行业客户属于后续拓展方向。产品会先在中小银行场景完成 POC 验证，再根据不同客户的交易特点增加行业规则和专项模块。

## 2. 客户痛点

客户通常已经具备基础预警能力，当前更大的工作量集中在预警之后的调查环节。调查人员需要从大量交易中找到真正重要的记录，判断账户之间是否存在关联，再将规则命中、交易明细和补充材料整理成审核人员能够复核的材料。

风险分数和规则编号本身也不能完全说明问题。审核人员通常还要回答风险为什么升高、哪些交易影响最大、资金经过了哪些账户以及是否还需要补充材料。调查过程如果分散在多个系统中，后续复核和监管检查也会增加工作量。

## 3. 产品与服务

链鉴 AML 是一套反洗钱调查辅助系统。它从账户、交易和案例数据开始，经过数据整理和质量检查后生成预警案件，再将交易时间线、账户画像、资金关系、评分原因和调查报告放在同一个案件中。

### 3.1 产品边界与人工审核责任

系统用于辅助识别可疑行为、辅助开展案件调查和辅助生成报告草稿。它帮助调查人员整理交易事实、资金关系、证据来源和风险原因，案件的最终结论由客户授权的人工审核人员作出。

账户处置、交易拦截、账户冻结和正式报送按照客户现有的制度、审批流程和相关系统执行，链鉴 AML 提供案件事实、证据链、评分解释和报告草稿作为审核依据。系统不自动冻结账户、不自动报送，也不替代人工判断。产品定位、销售材料、演示内容和合同条款均以这一边界为准。

| 事项 | 系统提供的内容 | 最终责任 |
|---|---|---|
| 可疑行为识别 | 规则分析、账户画像、资金关系和风险提示 | 人工复核识别结果 |
| 案件调查 | 交易查询、证据整理和调查任务 | 调查人员核验事实 |
| 报告形成 | 结构化报告草稿和证据引用 | 审核人员审核、修改和确认 |
| 风险结论 | 风险原因和待核查事项 | 客户授权人员作出最终结论 |
| 账户及交易处置 | 提供调查依据和审核材料 | 由客户现有流程和授权系统执行 |

系统可以通过规则分析识别循环交易、拆分转账、资金归集、快速转移和多跳转移等行为，也可以通过资金关系图谱查看账户之间的交易关系和资金路径。风险评分会展示主要影响因素，帮助审核人员理解分数来源。

系统还提供智能调查助手。它可以按照调查问题查询规则、交易、账户和资金路径，并将结果整理成带有证据来源的报告草稿。审核负责人可以查看调查材料、补充文件和审核记录，再确认风险、驳回预警或要求补充调查。

对于需要长期维护的客户，我们提供持续改进服务，包括数据质量检查、规则效果评估、预警处理分析、改进建议、验证测试和版本复盘。系统可以根据指标变化提示潜在问题，改进方案经过人工评估、验证和审批后再进入客户环境。

## 4. 客户收益

客户收益主要体现在调查人员工作量下降、重点案件处理能力提高和审核过程更容易复核。系统可以将关键交易、账户关系和规则依据集中到案件中，减少重复查询和材料整理；报告草稿可以减少基础文字编写工作；审核记录和证据引用可以帮助客户保留清晰的判断过程。

收益需要以客户自身数据进行 POC 测算。例如，若某机构每天产生 1 万条预警，每条预警平均需要人工处理 10 分钟，系统经验证将重点审查工作量降低 30%，则理论上每天可以减少 3 万分钟的重复处理工作，约合 500 人时或 62.5 人天。这个结果只是测算示例，实际数值需要根据客户基线、案件复杂度和审核人员的实际使用情况确认。

## 5. POC 验收标准

POC 的成功标准由客户和项目团队在开始前共同确认，重点看识别效果、调查效率、证据质量和系统运行情况。

| 指标 | 验收方式 | 建议口径 |
|---|---|---|
| 可疑交易召回率 | 使用客户授权的历史数据和标签进行对比 | 不低于客户现有基线，具体目标根据样例数据确定 |
| 误报率或预警压降比例 | 对比系统上线前后的驳回率和重点审查量 | 在召回率可接受的情况下，误报率或重复审查量有所下降 |
| 单案例调查时间 | 记录调查人员从打开案件到形成审核材料的时间 | 相比客户现有流程缩短，目标由历史案件测时确认 |
| 报告生成时间 | 记录调查任务完成到报告草稿生成的时间 | 在约定时间内生成结构化草稿 |
| 证据链完整率 | 抽查规则、交易、账户和报告结论的引用关系 | 关键结论能够找到对应来源 |
| 审核人员认可率 | 由合规人员对事实、评分原因和报告材料进行评价 | 达到双方确认的认可水平 |
| 系统稳定性 | 观察数据导入、案件查询、调查任务和报告生成 | 核心流程在约定数据量和并发范围内稳定运行 |

POC 还需要完成数据接入说明、规则配置表、案件样例、报告样例和评估报告。真实生产效果需要使用经过授权的数据独立验证。

## 6. 收费方式

链鉴 AML 当前采用三种商业模式。POC 是正式合作前的验证阶段，SaaS 形态仍在后续规划中，不作为现阶段的销售方式。

| 商业模式 | 初步价格假设 | 主要内容 |
|---|---:|---|
| 私有化部署 | 80–300 万元 | 软件授权、部署实施、数据接入、规则配置、人员培训和首年服务 |
| 持续运营服务 | 软件费用的 15%–25%/年 | 运行监控、规则评估、参数校准、版本升级和运维支持 |
| 模块化及定制交付 | 按项目评估 | 资金图谱、Agent 调查、行业规则、数据接口和专项功能扩展 |

## 7. 交付范围

客户负责提供经过授权的账户、交易、案例和必要标签数据，并负责脱敏、字段说明、网络环境、服务器或虚拟机、访问权限和基础设施。团队负责软件部署、标准数据接入、初始规则配置、基础校准、测试、操作培训和上线支持。

硬件采购、客户现有系统改造、外部数据购买、长期驻场、超出约定范围的历史数据迁移和大规模数据治理默认不包含在软件费用中。简单阈值调整可以纳入年度持续服务；新增行业规则、复杂关系规则、新数据接口和专门页面根据工作量另行评估。

## 8. 竞争优势

| 对比项 | 传统规则系统 | 通用大模型方案 | 链鉴 AML |
|---|---|---|---|
| 复杂资金链识别 | 主要依赖单笔规则 | 依赖提示词和已有数据 | 规则分析与资金关系图谱结合 |
| 结果说明 | 以规则编号和命中条件为主 | 需要人工核对事实 | 证据链、交易明细和资金路径共同说明 |
| 人工审核 | 通常有审核功能 | 通常需要另行组织流程 | 案件、证据、调查和审核记录统一保存 |
| 报告整理 | 主要依赖人工填写 | 生成较快但需要核对 | 基于调查事实生成报告草稿 |
| 后续改进 | 主要依靠人工维护规则 | 主要调整提示词或模型 | 监控、评估、改进建议、验证和版本记录 |

链鉴 AML 的差异体现在统一的工作流程上，预警、资金关系、证据、智能调查和人工审核都在同一个案件中衔接。客户可以先从一个具体问题或一个模块开始，再根据 POC 结果决定是否扩大使用范围。

## 9. 三年规划

三年规划以中小银行场景为主线。第一年重点完成 2 至 3 个 POC，整理数据接入、规则配置和部署材料，争取形成 1 至 2 个正式项目；第二年重点提高标准化交付能力，累计服务 4 至 6 家付费客户，并开展持续改进服务；第三年在保持中小银行为主的基础上，选择性拓展支付、消费金融和跨境支付场景，累计服务客户按 8 至 12 家进行规划。

| 年度 | 产品重点 | 客户和销售重点 | 收入规划口径 |
|---|---|---|---|
| 第一年 | POC 产品包、数据接入模板、验收指标 | 2–3 个 POC，争取 1–2 个付费项目 | 初步规划 100–300 万元 |
| 第二年 | 私有化交付、权限、监控和持续服务 | 累计 4–6 家付费客户，发展合作伙伴 | 初步规划 400–800 万元 |
| 第三年 | 资金关系、智能调查和行业规则模块化 | 累计服务 8–12 家客户，选择性拓展行业 | 初步规划 800–1500 万元 |

以上目标属于规划区间，不代表已经实现的收入或客户数量。每年应根据真实合同、实施工时、客户定制比例、基础设施成本和续费情况重新测算。

## 10. 说明

链鉴 AML 当前适合用于比赛展示、客户交流和 POC 验证，真实生产部署需要根据客户数据授权、权限、安全、性能和运维要求进一步评估。系统定位为反洗钱调查辅助工具，客户授权人员负责最终审核和业务判断。

## 11. 商业化验证与待确认问题

当前方案中的价格、客户数量和交付周期属于初步规划，后续需要通过真实客户交流和 POC 逐步验证。以下问题会直接影响采购决策和交付成本，因此在签约前应逐项确认。

| 待确认问题 | 需要确认的内容 | 建议验证方式 |
|---|---|---|
| 持续迭代服务的付费意愿 | 客户是否愿意为规则评估、数据质量检查和版本复盘单独付费 | 客户访谈、服务报价和试运行反馈 |
| 中小银行预算水平 | 目标客户是否具备 50 万元以上的项目预算 | 了解同类项目预算、采购流程和招投标范围 |
| POC 数据条件 | 客户能否提供经过脱敏和授权的账户、交易、案例及标签数据 | 在 POC 前确认字段、数据量、标签和审批安排 |
| 识别效果 | 误报率、召回率和重点审查量能否达到客户要求 | 使用客户历史数据进行回放和对比测试 |
| 昇腾环境适配 | 信创环境是否会增加模型部署、测试和运维成本 | 在目标环境完成小范围技术验证并记录实施工时 |
| 数据接入标准化 | 不同机构的数据结构能否通过统一字段和映射模板接入 | 选取不同机构样例测算接入周期和定制量 |
| 客户定制工作量 | 规则、接口、权限、历史数据和页面流程需要多少定制 | 在 POC 中记录实施人天和定制项，形成后续报价依据 |

这些问题是从 POC 走向正式项目必须完成的验证，不作为当前产品效果或收入的承诺。验证结果应回填到验收标准、报价、交付范围和后续规划中。
