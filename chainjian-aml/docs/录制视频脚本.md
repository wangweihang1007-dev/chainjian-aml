# 链鉴 AML 五分钟全功能演示视频脚本

> 目标：不仅展示页面功能，还要讲清楚数据底座、证据约束、多 Agent、Harness 工程和自进化闭环。
>
> 建议时长：5 分钟；旁白约 1100–1300 字；主线使用一个高风险预警案件。

## 录制前准备

- 浏览器打开 React 工作台，确认显示“后端已连接”。
- 预先选一个同时具备规则命中、关键交易、资金路径和风险评分的案件，实际案件编号以页面为准。
- 准备两个画面：工作台浏览器，以及项目目录下的终端。终端只展示命令和结果，不展示密钥、密码或个人信息。
- 如果 Agent、Neo4j 或评估接口加载较慢，可以先准备缓存结果；旁白必须以现场真实状态为准。

## 时间轴

| 时间 | 画面 | 必讲内容 |
|---|---|---|
| 0:00–0:25 | 开场 + 架构简图 | 产品定位和四个核心亮点 |
| 0:25–0:55 | 数据仓库/终端 | ODS-DWD-DWS-ADS、标签隔离、可追溯 |
| 0:55–1:50 | 预警中心 + 案件详情 | 规则、证据链、关键交易、评分解释 |
| 1:50–2:30 | 图谱 + 账户画像 | 多跳资金关系和反事实分析 |
| 2:30–3:25 | Agent 分析编排 | Supervisor、专家 Agent、Evidence Judge、报告 |

## 逐镜头脚本

### 0:00–0:25｜开场：四个核心亮点

**画面**：先展示项目名称和总体架构简图，再切入 React 工作台。

**旁白**：

> 大家好，这是链鉴 AML，面向反洗钱调查的证据链审查平台。
> 我们的核心亮点有四个：第一，数据从原始交易到页面查询经过分层数仓治理；第二，风险结论必须由真实交易和资金路径证据支撑；第三，多个专业 Agent 协作调查，但由 Evidence Judge 做证据质检；第四，系统通过 Harness 和自迭代机制，做到可验证、可监控、可持续改进。
> 下面用一个预警案件，演示从数据到审核的完整闭环。

### 0:25–0:55｜数据底座：不是直接把 CSV 喂给模型

**画面操作**：切到项目文档 `docs/data-warehouse.md` 或提前准备的架构图；展示终端中的数据仓库统计。镜头依次指向 ODS、DWD、DWS、ADS 和 APP。

**旁白**：

> 链鉴不是把原始 CSV 直接交给规则或大模型，而是先进入 SQLite 分层数据仓库。
> ODS 保存原始导入批次，保证来源可追溯；DWD 保存清洗标准化后的账户和交易明细；DWS 计算账户日汇总、交易对手和风险特征；ADS 为仪表盘和页面提供查询快照；APP 层则保存预警、证据、审核和报告等业务记录。
> 评估标签单独隔离在 ODS 评估区，只能用于离线评估，不能进入在线规则、图谱或 Agent 推理。这保证了演示中的风险判断没有偷看答案。

**屏幕字幕**：`ODS 原始层 → DWD 明细层 → DWS 特征层 → ADS 应用层 → APP 业务闭环`

### 0:55–1:50｜预警和证据链：从规则命中到可解释案件

**画面操作**：回到“预警中心”，展示按案件号/账户号筛选；点击案件；展示案件头部、关键交易、证据链、资金路径；打开“评分解释”和“反事实分析”。

**旁白**：

> 在预警中心，每条案件都有稳定的案件编号、风险分、风险等级、命中规则和处理状态。点击案件进入调查工作台。
> 系统支持循环交易、拆分转账、资金归集、资金发散、快速转移和多跳资金等行为规则。案件详情不会只给一个风险标签，而是同时展示关键交易、交易时间线、付款方、收款方、金额和交易编号。
> 证据链会把规则命中、关键交易、账户画像和资金路径统一起来。评分解释进一步拆出每个因素的贡献，并能通过反事实分析回答：如果移除某笔关键交易或某个风险因素，案件分数会下降多少。
> 所以调查人员看到的不是一个黑盒分数，而是一套可以逐项核对、可以回放的事实链。

### 1:50–2:30｜图谱智能：识别单笔交易背后的关系网络

**画面操作**：点击“账户画像”，展示交易笔数、对手方、活跃天数和风险特征；再进入“图谱调查”，拖动节点、缩放画布、点击一条关系。

**旁白**：

> 账户画像把账户的交易规模、对手方数量、活跃天数和行为特征聚合出来。
> 图谱调查则把账户作为节点、交易作为有方向的边，查看一到三跳的资金路径。红色或高亮关系代表直接预警证据，其他节点是关联核查线索。
> 点击关系可以回到交易编号、金额和触发原因；点击节点可以查看它在当前资金网络中的角色。
> 图谱优先使用 Neo4j，服务不可用时降级到 SQLite 事实表，并明确标记数据源和能力边界，避免把降级结果伪装成完整图谱。

### 2:30–3:25｜多 Agent：动态分工，证据约束输出

**画面操作**：进入“分析编排”，输入：`请分析当前案件的主要风险、关键证据和下一步核查建议。` 点击开始；展示任务时间线、Agent 状态、Evidence Judge、证据索引和报告。

**旁白**：

> 现在进入分析编排。Supervisor Agent 先读取当前案件和账户画像，再根据命中规则动态分配任务。
> Rule Agent 解释规则命中；Transaction Agent 分析快进快出、高频和大额行为；Graph Agent 查询一到三跳资金路径；Report Agent 汇总调查结果。
> 专家任务可以并行执行，Evidence Judge 会检查证据覆盖、任务失败、数据源降级和证据 ID 是否可回溯。如果证据不足，最多触发一次补查；仍然不足就输出 `NEEDS_MORE_EVIDENCE`，转人工补充。
> 页面展示每个任务的状态、来源、可信度和证据数量。模型只负责组织事实，不允许补造账户、金额、交易或资金路径。
> 最终输出包含风险摘要、关键证据、资金链路、待核查事项和结构化调查报告。

### 3:25–4:10｜Harness 工程：把“能运行”变成“可重复验证”

**画面操作**：切到终端，在 `chainjian-aml` 目录展示命令：

```powershell
python -m harness.run all
```

随后展示终端输出，或展示 `harness/README.md` 和 `harness/config.json` 中的验证套件与阈值。

**旁白**：

> 为了避免演示系统只在某一次手工操作中看起来正常，我们提供了 Verification Harness，作为本地可重复验证的统一入口。
> 一条命令会串起单元测试、代码编译、前端构建、接口冒烟和离线评估；也可以单独运行 unit、compile、frontend、smoke 和 eval 套件。
> 评估门禁从配置文件读取，比如整体 F1 以及重点规则的 Precision、Recall 阈值。阈值变更需要和基准结果一起评审。
> Harness 不会修改规则、标签或生产数据；服务失败、图谱降级、评估不可用都会留下明确结果，而不是用静默成功掩盖问题。
> 这就是项目的工程化亮点：功能、数据、评估和失败路径都能被重复验证。

### 4:10–4:45｜自进化：机器提案，人来审批

**画面操作**：回到“评估监控”，展示预警总数、待审核、Precision、Recall、F1 和规则级指标；指向“自迭代中心”和“运行一轮诊断”。如现场允许，点击一次并展示生成的提案状态。

**旁白**：

> 最后看自迭代中心。系统持续采集数据质量、金额分布、规则命中量、预警量、审核确认率和驳回率，并结合离线评估判断是否出现漂移或规则失效。
> 当指标触发黄线或红线，流程会进入监控、评估、诊断和提案阶段，自动生成带有触发信号、问题归因、变更建议、预期收益和回滚方案的迭代提案。
> 但“自进化”不是自动改规则，更不是自动上线。高影响的规则、评分权重、风险等级和报告口径变更，必须经过人工决策门、回归测试、离线评估和发布审批。
> 所以系统实现的是“机器监测、机器诊断、机器提案、人审批、机器验证”的安全闭环。

### 4:45–5:00｜审核闭环与收尾

**画面操作**：回到案件详情，点击“人工审核”；展示“确认风险、驳回预警、需要补充调查”和审核备注；最后点击“生成调查报告”，停留在证据链与报告卡片同屏画面。

**旁白**：

> 调查结果最终回到人工审核。审核人和备注必填，系统记录原状态、新状态、操作人、时间和审计日志；报告也可以导出为 Markdown，供后续复核。
> 链鉴 AML 的价值，是把分层数据仓库、可解释规则、资金图谱、多 Agent 调查、Harness 验证和自迭代治理连接成一个闭环。
> 它定位于合规调查辅助，不自动冻结账户、不拦截交易，也不替代授权人员作出最终认定或监管报送决定。谢谢观看。

## 录制注意事项

- 数据仓库和 Harness 不一定有对应的前端页面，建议用“浏览器 + 终端 + 架构图”三段式剪辑，工程亮点要保留画面证据。
- 自迭代要明确说“生成提案并等待人工审批”，不要说成系统会自动修改规则或自动发布。
- 评估指标必须注明是离线指标，不要把合成数据结果表述为生产效果。
- 如果 Neo4j 不可用，直接展示 SQLite fallback 和数据源说明；如果模型不可用，展示确定性本地回退或失败状态。
- 不要展示密码、API Key、数据库敏感信息或真实客户资料。
